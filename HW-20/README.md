- https://www.exploit-db.com/exploits/49757
- Суть уязвимости: в исходный код vsftpd 2.3.4 был внедрён бэкдор. Если в качестве имени пользователя передать строку, заканчивающуюся на :), сервер открывает командную оболочку (shell) на порту 6200 с правами root — без аутентификации.

2. UnrealIRCd 3.2.8.1 — Backdoor Command Execution:
- https://www.exploit-db.com/exploits/16922
- Суть уязвимости: в дистрибутив UnrealIRCd 3.2.8.1 был внедрён троянский код. Если отправить на порт 6667 строку, начинающуюся с AB;, всё что после неё передаётся напрямую в system() — то есть выполняется как системная команда. Аутентификация не требуется.

3. Samba smbd 3.0.20 — Username Map Script Command Injection
- https://www.exploit-db.com/exploits/16320
- Суть уязвимости: функция MS-RPC в Samba 3.0.0–3.0.25rc3 передаёт имя пользователя без фильтрации спецсимволов в /bin/sh. Если в конфигурации включена опция username map script (а на Metasploitable она включена), атакующий может передать имя пользователя с shell-метасимволами — и сервер выполнит произвольную команду от имени root. Аутентификация не требуется.

### Задание 2

1. SYN-сканирование (nmap -sS)- классическое «полуоткрытое» сканирование. nmap не устанавливает полноценное TCP-соединение, что исторически позволяло избегать логирования в приложениях.
В трафике выглядит как цепочка быстрых одиночных SYN запросов на разные порты.
Ответ сервера:
- Порт открыт: Сервер честно отвечает пакетом SYN, ACK, ожидая завершения соединения. Но nmap вместо финального ACK отправляет RST (Reset), мгновенно разрывая связь.
- Порт закрыт: ОС сервера сразу возвращает пакет RST, ACK.

![Скрин к 2му заданию 1]()

2. FIN-сканирование (nmap -sF) - относится к категории "инверсных" (стелс) сканирований. Основано на спецификации RFC 793 для протокола TCP. Согласно стандарту, если пакет приходит на закрытый порт без флагов SYN, RST или ACK, устройство должно ответить RST. Если порт открыт — пакет должен быть проигнорирован.
Как выглядит в трафике: nmap отправляет пакет, в котором выставлен только один флаг — FIN (обычно FIN используется для закрытия соединения, но здесь оно даже не открывалось).
Ответ сервера:
- Порт открыт: Metasploitable (на базе Linux) строго следует RFC и вообще ничего не отвечает. nmap видит тишину и маркирует порт как open|filtered.
- Порт закрыт: Сетевой стек Linux возвращает пакет RST, ACK.

![Скрин к 2му заданию 2]()

3. Xmas-сканирование (nmap -sX) - логика работы полностью идентична FIN-сканированию, меняется только набор флагов. В поле флагов заголовка TCP одновременно загораются несколько битов.
Как выглядит в трафике: Отправляются пакеты с тремя включенными флагами: FIN, PSH, URG.
Ответ сервера:
- Порт открыт: Сервер молчит (игнорирует некорректный пакет по RFC 793).
- Порт закрыт: Сервер отвечает пакетом RST, ACK.

![Скрин к 2му заданию 3]()

4. UDP-сканирование (nmap -sU) - в отличие от TCP, UDP — это протокол без установления соединения. Здесь нет флагов состояния, поэтому сканирование происходит сложнее и медленнее.
Как выглядит в трафике: nmap отправляет пустые UDP-пакеты на целевые порты (на некоторые известные порты, вроде DNS 53 или NTP 123, он может отправлять специфический для протокола payload).
Ответ сервера:
- Порт закрыт: Служба на сервере не слушает этот порт. ОС сервера генерирует служебный ответ протокола ICMP: ICMP Destination Unreachable (Port unreachable) (Тип 3, Код 3).
- Порт открыт: Приложение получает пустой UDP-пакет. Чаще всего оно его просто игнорирует и ничего не отправляет в ответ. nmap, не получив ответа (и не получив ошибку ICMP), предполагает, что порт открыт (статус open|filtered). В редких случаях приложение может ответить своим UDP-пакетом (например, DNS-сервер ответит ошибкой формата запроса) — тогда статус будет гарантированно open.
